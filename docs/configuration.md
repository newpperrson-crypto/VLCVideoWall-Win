# Настройка

Файл `Mosaic.conf` лежит рядом с `VLCVideoWall.exe` и является **единственным**
источником правды о стене: его правят в приложении (а при необходимости — руками).

`Mosaic.active.vlm` создаётся сторожем из `Mosaic.conf` при каждом запуске и
перезаписывается при любом изменении настроек, поэтому править его вручную
бессмысленно — изменения пропадут. Это производный рабочий файл, не настройка.

Отправная точка — [`config/Mosaic.conf.example`](../config/Mosaic.conf.example).

## Ключи

| Ключ | Значения | По умолчанию | Смысл |
|---|---|---|---|
| `layout` | `КОЛОНКИxСТРОКИ`, `1x1 … 16x16` | `2x2` | Сетка. Всего не больше 16 окон. |
| `canvas` | `ШИРИНАxВЫСОТА` | `1920x1080` | Разрешение собираемой картинки. |
| `cam ИМЯ URL` | по строке на камеру | — | Источник плитки. Порядок строк = порядок окон. |
| `off cam ИМЯ URL` | по строке на выключенную камеру | — | Камера остаётся в списке, но не выводится на стену. |
| `windowed` | `yes` / `no` | `no` | Запускать стену в окне размером с полотно вместо полноэкранного режима. |
| `audio` | имя камеры или пусто | пусто | Звук этой камеры выводится отдельно; пусто — без звука. |
| `volume` | `0 … 100` | `80` | Громкость звука в процентах. |
| `vlcpath` | полный путь к `vlc.exe` | пусто | Отменяет автопоиск. |
| `logdir` | папка | папка программы | Куда писать `mosaic_watchdog.log`. |
| `logkeep` | дни, `0` — не удалять | `30` | Срок хранения журналов. |

Строки, начинающиеся с `#`, и пустые строки игнорируются.

## Окна и порядок заполнения

Окна заполняются **слева-направо, затем следующая строка**: `ch1` — левый верхний
угол, `ch2` — справа от него, `ch4` открывает вторую строку сетки из трёх колонок.

* Строк `cam` больше, чем ячеек: лишние игнорируются (побеждает сетка).
* Строк меньше, чем ячеек: оставшиеся ячейки показывают полотно.
* Поменять два окна местами — поменять местами их строки `cam`.
* Добавить или удалить камеру — добавить или удалить строку.
* Изменить число окон — изменить `layout` (`3x2` = 6, `3x3` = 9, `4x4` = 16).
  Больше 16 обрезается до 16.

`ИМЯ` должно быть уникальным и латинским (`ch1`, `cam_lobby`, `entrance`).
Повторяющиеся и нелатинские имена при сохранении заменяются на `chN`.

## Полотно и фоновые изображения

## Стена в окне

По умолчанию стена занимает весь экран (полноэкранный режим VLC). Если в
`Mosaic.conf` указано `windowed = yes` (или включена галочка «в окне (размер =
полотну)»), VLC запускается обычным окном с заголовком.

**Политика размеров.** Действует одно правило: на экране всегда помещается **всё
окно целиком** — и картинка, и заголовок с рамкой.

- Если полотно с рамкой помещается в рабочую область монитора — клиентская область
  равна полотну, картинка выводится 1:1 без масштабирования.
- Если не помещается (например, полотно 1920×1080 на экране 1920×1080, где часть
  высоты занята панелью задач, или 4K на 1080p) — клиентская область уменьшается с
  сохранением пропорций. Картинка масштабируется целиком, ничего не обрезается и не
  искажается, заголовок остаётся видимым и рабочим для перетаскивания.

Размеры считаются по **рабочей области** монитора, на котором стоит окно (без панели
задач), в физических пикселях; учитывается масштаб Windows 100%, 125%, 150% —
двойного масштабирования не возникает.

Окно сдвигается вправо и вниз на 10% рабочей области, если при этом остаётся место;
при нехватке места сдвиг уменьшается, но окно не выходит за край экрана.

В журнал сторож пишет фактические значения: полотно, клиентскую область, внешний
прямоугольник окна, рабочую область, процент масштабирования и, если он меньше 100%,
причину уменьшения. По этой строке можно проверить, с каким масштабом стена реально
показывается на конкретном мониторе.

При масштабе экрана отличном от 100% размер пересчитывается с учётом DPI: окно
получается ровно `canvas` физических пикселей.

Мозаика собирается в размере `canvas`: параметры `mosaic{width=W,height=H}`, и
каждая плитка получает `W/колонки × H/строки` (округление вниз до чётного).

| Пресет | Размер | Файл полотна |
|---|---|---|
| HD | 1280×720 | `bg_1280x720.jpg` |
| Full HD | 1920×1080 | `bg_1920x1080.jpg` |
| 2K | 2560×1440 | `bg_2560x1440.jpg` |
| 4K | 3840×2160 | `bg_3840x2160.jpg` |
| SXGA (5:4) | 1280×1024 | `bg_1280x1024.jpg` |
| своё | 640×480 … 3840×2160 | `bg_custom.jpg` |

Полотна — обычные чёрные JPEG. Для пресетов файл называется по размеру; любое
своё разрешение использует один и тот же `bg_custom.jpg`, который перезаписывается
при смене размера, поэтому эксперименты не засоряют папку. Если файла нет или его
пиксельный размер не совпадает с `canvas`, сторож перерисовывает его при запуске и
пишет в журнал `полотно WxH -> файл`.

Полотно 4K — это примерно вчетверо больше пикселей, чем Full HD, и на панели
1920×1080 разницы не видно. Выбирайте родное разрешение монитора.

## Адреса RTSP и пароли

```
rtsp://ЛОГИН:ПАРОЛЬ@АДРЕС:554/ПУТЬ
```

Пути у камер разные, их описывает производитель. Два практических правила:

1. **Кодируйте** символы `@ : / ? # % +` внутри логина и пароля:
   `p@ss:word` превращается в `p%40ss%3Aword`. Незакодированный `@` разрывает URL
   не в том месте, и камера отвечает `401`.
2. **Проверьте адрес в самом VLC** (`Медиа → Открыть URL`) до добавления в стену.
   Если VLC не проигрывает адрес, стена его тем более не проиграет.

Некоторые камеры ограничивают число одновременных сессий. Стена открывает по
сессии на плитку, поэтому камера, которая терпит двух зрителей, будет терять
плитки уже на сетке 3×3.

## Журналы

`mosaic_watchdog.log` фиксирует: параметры запуска, найденный путь к VLC, каждое
изменение состояния канала, результат каждой проверки RTSP и каждое
восстановление с длительностью простоя. Файлы старше `logkeep` дней удаляются при
запуске.

## Служебные файлы

Эти файлы создаются автоматически и не являются настройками — их не нужно править
и не нужно копировать на другую машину:

| Файл | Кто создаёт | Что это |
|---|---|---|
| `Mosaic.active.vlm` | сторож при каждом запуске | раскладка для VLC, собирается из `Mosaic.conf` |
| `bg_<W>x<H>.jpg`, `bg_custom.jpg` | сторож | чёрное полотно под разрешение стены |
| `vlc.pid` | сторож | PID и время старта своего VLC: по нему приложение отличает свой плеер от чужого |
| `watchdog.heartbeat` | сторож | отметка «сторож жив» раз в секунду: приложение судит о живости по ней, а не по открытому порту |
| `watchdog.status` | сторож | подтверждение, что VLM ответил: время, `vlm=ok|fail`, число играющих каналов |
| `mosaic_watchdog.log` | сторож | журнал работы и восстановлений |
| `stop.flag` | приложение | команда сторожу «остановись», живёт доли секунды |
| `VLCVideoWall.settings.json` | приложение | окно, трей, автозапуск — настройки самой программы |

Пароль HTTP-интерфейса VLC генерируется заново на каждый запуск и в журнал не
пишется, поэтому по логу восстановить доступ к интерфейсу нельзя.

## Интервалы опроса камеры

Проверка камеры запросом `OPTIONS` выполняется не чаще, чем нужно:

| Ситуация | Интервал |
|---|---|
| камера недоступна по сети | 5 с (ждём возвращения связи) |
| порт открыт, RTSP молчит | 60 с (камера, похоже, блокирует клиента) |
| ответ `401/403` | 120 с, канал при этом не перезапускается |
| камера отвечает | 5 с |

Так неверный пароль не превращается в подбор: при опросе раз в 5 секунд камера
могла бы заблокировать IP клиента. После исправления пароля перезапустите стену
или приложение — интервал опроса сбросится.

## Проверка камеры

Перед перезапуском канала сторож отправляет запрос `OPTIONS` с абсолютным
RTSP-адресом (как требует RFC 2326) и поддерживает оба способа авторизации:
Basic и Digest. Ответ `401` сначала означает «сервер предложил Digest» и только
после ответа на челлендж трактуется как неверный логин или пароль. Поэтому
рабочая камера с Digest-аутентификацией больше не попадает в двухминутную паузу.

## Звук

VLC собирает мозаику только из видео: у `mosaic-bridge` в VLC 3 нет аудиопараметров,
поэтому сама стена звука не воспроизводит. Звук одной выбранной камеры выводит
отдельный процесс VLC без видео — им управляет сторож.

- `audio = ch3` — камера, звук которой слушаем. Пусто — звука нет.
- `volume = 80` — громкость 0…100.
- В приложении источник выбирается списком «Звук:» на вкладке «Камеры и сетка» или
  кликом по плитке на вкладке «Стена»: первый клик делает камеру источником, повторный
  по той же плитке выключает и включает звук.
- На самой стене над плиткой звучащей камеры показывается значок динамика: зелёный —
  звук включён, красный с перечёркиванием — выключен. Клик по значку переключает звук.

Служебные файлы (создаются рядом с `Mosaic.conf`):

| Файл | Кто пишет | Что внутри |
|---|---|---|
| `audio.cmd` | приложение | команда сторожу: `source=<камера>`, `mute=on/off`, `volume=0..100` |
| `audio.status` | сторож | время, `source`, `muted`, `volume`, `playing` — по нему рисуется значок |
| `audio.pid` | сторож | PID и время старта аудиопотока |

Камера должна отдавать звуковую дорожку: если в её RTSP-потоке нет audio, звука не
будет (сторож запустит поток, но он будет молчать). Проверить можно в VLC:
«Инструменты → Сведения о кодеках» — в списке должна быть звуковая дорожка.

Одновременные сеансы: стена и аудиопоток подключаются к камере двумя RTSP-сеансами.
Большинство моделей это допускают; если камера ограничивает число сеансов, звук
следует отключить (`audio =`).

## Состояния стены в приложении

Зелёное «работает» требует трёх подтверждений: живой сторож (`watchdog.heartbeat`),
свой процесс VLC (`vlc.pid`) и свежее подтверждение VLM (`watchdog.status`, `vlm=ok`).
Открытый порт 4212 сам по себе зелёного статуса не даёт.

| Состояние | Что означает | Что доступно |
|---|---|---|
| работает | сторож, свой VLC и VLM подтверждены | остановить, перезапустить |
| запускается… | сторож есть, VLC ещё поднимается | остановить |
| сторож работает, VLC не отвечает | порт есть, но VLM не подтверждает ответ | остановить, перезапустить |
| VLC без сторожа | плеер остался без присмотра — типично после аварийного завершения сторожа | остановить |
| остановлена | компонентов нет | запустить, перезапустить |

Остановка считается успешной только когда завершились **и** свой VLC, **и** сторож.
Посторонние экземпляры `vlc.exe` не завершаются никогда — если такой запущен,
приложение скажет об этом в сообщении.

`vlc.pid` удаляется только после подтверждённого завершения процесса. Если VLC не
умер за отведённое время (завис, отказ в доступе), файл **остаётся** — по нему
приложение снова найдёт свой процесс и повторит остановку. Сохранённый `vlc.pid`
сам по себе не ошибка, а признак того, что остановку нужно повторить.
